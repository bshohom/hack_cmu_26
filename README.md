# hack_cmu_26 — integrated system

Three pieces, one flow: **Streamlit agentic interface** (`Hack_CMU_Agentic_Interface/.../app.py`,
structured questions → candidate → live optimization → printable STL) · **`to_agent`** (this package:
SIMP topology optimization on torch-fem, cost estimate, FE check) · **`surfcap`** (in-repo photo
registration; its `target.json` feeds desk measurements with a confidence gate). Warm-start geometry is
either an imported triple (`<mesh> + _dimensions.txt + _particles.obj`, three demo parts at the repo root)
or **generated by Grok** as a validated trimesh script. See
`Hack_CMU_Agentic_Interface/HackCMU_mechanical_design_copilot_drive_20260912_014958/README_INTEGRATION.md`.

## Install (teammates and agents)

Registration is vendored in this repo (`surfcap/`). Do **not** clone or submodule the private
HackCMU checkout. Agents should follow this sequence on a Linux machine with an NVIDIA GPU
(~10 GB VRAM; RTX 3080 was the verified path).

```bash
git clone https://github.com/bshohom/hack_cmu_26.git
cd hack_cmu_26
git lfs pull

conda create -n hack_cmu_26 python=3.12 -y
conda activate hack_cmu_26

# Install CUDA torch *before* the rest. Pick the index that matches the driver:
#   cu128 — RTX 50-series / sm_120
#   cu130 — CUDA 13.0 driver (verified: torch 2.10.0+cu130 on RTX 3080)
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

pip install -e ".[dev,registration]"
# Depth Anything 3's own pyproject pins numpy<2 and will try to rebuild pandas.
# Always install it with --no-deps after the extras:
pip install "depth-anything-3 @ git+https://github.com/ByteDance-Seed/Depth-Anything-3.git@3d835ec1a5802d64a8b8b15f817a1ab54809bfe4" --no-deps
```

First live reconstruct also downloads Hugging Face weights:
- `depth-anything/DA3-LARGE-1.1` (public, ~1.6 GB)
- `facebook/sam3` (**gated** — accept the model terms, then `huggingface-cli login` / set `HF_TOKEN`)

Smoke-check, then run the UI from the **interface directory** (not the repo root):

```bash
python -c "import torch, pycolmap, shapely; from depth_anything_3.api import DepthAnything3; print('cuda', torch.cuda.is_available())"
python -m surfcap --help
cd Hack_CMU_Agentic_Interface/HackCMU_mechanical_design_copilot_drive_20260912_014958
streamlit run app.py --server.fileWatcherType none
```

In the sidebar: **Component Mode → Reconstruct grounding surface**.
- **Run bundled table_a capture** uses `examples/surfcap/table_a` (needs `git lfs pull`).
- Or **Capture photos** (8–18 jpg/png/heic of the table + credit card) then **Run grounding-surface reconstruction**.
- Confirm the pre-filled desk thickness, then **Load Small Bottle Holder Case (live TO)** (or type a request). Bottle size/mass are entered, not measured from a bottle photo.

The chat-column **Upload a photo of the desk / bottle** is a single image for Cursor scene analysis only; it does not run surfcap.

Optional env overrides (see `.env.example` in the interface folder):

```bash
SURFCAP_PYTHON=/path/to/python-with-registration-extras
SURFCAP_MODE=live   # set off in tests or to disable reconstruction
```

Demo problems can also run headless: `to-agent make-problem desk_bag_hook && to-agent run data/desk_bag_hook_problem.yaml --out out/hook`.

## Grounding-surface registration

The Streamlit sidebar guides and runs the in-repo `surfcap` pipeline
from 8–18 phone photos (14–18 recommended) containing a credit-card-sized reference on
the mount surface. The CV stack runs as an isolated subprocess and returns `target.json`;
this project converts its metres to mm and only pre-fills measurements whose scale and
provenance are trustworthy. The user still confirms them before design.

`tools/registration.py` is the callable skill boundary: `run_registration(...)` reconstructs
a new capture, while `load_registration_output(...)` consumes an existing output and
`run_sample_registration("table_a")` reconstructs the bundled capture. A hybrid mesh next to
`target.json` contributes geometry statistics; scale and measurement provenance come from
the adjacent contract. The sidebar's **Run bundled table_a capture** button exercises this
path, and the bottle-holder live-TO preset uses the confirmed registered thickness.

Install is in **Install (teammates and agents)** above. `python -m surfcap ... --recon-mode sfm_tsdf` is the explicit CLI; the Streamlit skill invokes the same flags. Generated photo captures and reconstruction artifacts stay under the interface's `generated/registration/` directory and are gitignored. Phase one does not reinterpret surfcap's card-centred frame as `desk_edge_frame` or feed its mesh into topology; it uses the reconstructed surface as reviewable registration evidence and trusted scalar input.

# to_agent — agent-facing 3D topology optimization on torch-fem

Turns a plain-data problem description (regions, supports, loads, material, volume fraction)
into a hex-grid SIMP topology optimization on [torch-fem](https://github.com/meyer-nils/torch-fem)
and writes a printable STL plus diagnostics. The agent layer only has to emit a `TOProblem` YAML.

## Setup (fresh conda env, GPU)

```bash
conda create -n hack_cmu_26 python=3.12 -y
conda activate hack_cmu_26
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128   # or cu130; see Install above
pip install -e ".[dev,registration]"
pip install "depth-anything-3 @ git+https://github.com/ByteDance-Seed/Depth-Anything-3.git@3d835ec1a5802d64a8b8b15f817a1ab54809bfe4" --no-deps
git lfs pull
python scripts/smoke_cantilever.py        # torch-fem's own example: numeric stack sanity check
python scripts/calibrate_cost.py          # times solves on this machine -> data/calibration.json
pytest -q
```

## Demo: desk-clamp cupholder

```bash
to-agent make-cupholder-problem            # dims + scan -> data/cupholder_problem.yaml
to-agent validate data/cupholder_problem.yaml
to-agent estimate data/cupholder_problem.yaml        # [ok|slow|too_big] + seconds/memory
to-agent run data/cupholder_problem.yaml --out out   # rho.vti, design.stl, history.png, render.png, result.json
to-agent run data/cupholder_problem.yaml --out out_fine --elem 3 --volfrac 0.15 --iters 60   # overrides
```

`python -m to_agent ...` works without the console script.

## Problem schema (`TOProblem`)

```yaml
units: {length: mm, force: N}
material: {name: PLA, E_MPa: 2300, nu: 0.35}
design_domain: {type: box, min: [x0, y0, z0], max: [x1, y1, z1]}   # or omit -> padded warm-start bounds
warm_start: [ {type: near_points, path: scan.obj, tol: 4.0} ]      # or inside_mesh / near_mesh
preserve:   [ ...regions held solid (attachment interfaces)... ]
void:       [ ...regions kept empty (cavities, the desk, clearance)... ]
supports:   [ {id: jaw, region: {...}, fixed_dofs: [x, y, z]} ]
load_cases: [ {id: drink, region: {...}, force_N: [0, 0, -10], weight: 1.0} ]   # total force over region nodes
safety_factor: 2.5          # multiplies every load
volume_fraction: 0.35       # of the design elements
target_element_size: 4.0    # mm; grid = design_domain / element size
filter_radius: 6.0          # default 1.5 * element size
max_iters: 40
```

Region primitives: `box`, `cylinder` (annulus via `r_min`, extent via `along`), `sphere`,
`halfspace`, `near_points` (point cloud ± tol), `inside_mesh` (watertight STL/OBJ),
`near_mesh` (surface ± tol), and `union` / `intersection` / `difference`.
Element classification priority: void > preserve > design. Loads/supports select grid nodes;
a region that selects no nodes raises an agent-readable error.

## Layout

```
to_agent/contracts.py      pydantic TOProblem + region primitives, YAML load/save
to_agent/regions.py        contains()/bounds() for every primitive
to_agent/ingest/           point clouds, meshes, dimension files
to_agent/meshing/          cube_hexa grid + element/node masks
to_agent/solver/simp.py    SIMP (OC update, sparse filter, multi-load-case) on torch-fem
to_agent/cost.py           time/memory estimate, calibrated by scripts/calibrate_cost.py
to_agent/postprocess/      VTI + STL export, history plot, render
to_agent/demo/{cupholder,hook,shelf}.py  part-specific builders (dims + scan -> TOProblem), registry.py
to_agent/integration/run.py     run_problem: grid -> masks -> SIMP -> exports -> FE post-check -> result.json
to_agent/integration/agentic.py TopologyInput dict -> TOProblem -> run -> TopologyOutput dict (interface adapter)
to_agent/integration/postcheck.py linear FE on the thresholded design: displacement, von Mises, factor of safety
to_agent/ingest/surfcap.py      surfcap target.json (m) -> mm measurements + confidence
```

## Data notes

- `cupholder_surface_particles.obj` is a 50k-point surface sample (no faces); its clamp levels
  (plate underside, hook top, spine) are measured from the scan by `demo/cupholder.py` and
  cross-checked against `cupholder_dimensions.txt`.
- Loads in `data/cupholder_problem.yaml` are placeholders (`confidence: assumed`).
- GPU: the model is built on CUDA when torch-fem supports it, otherwise the linear solver runs
  on CUDA with the model on CPU (`solver_mode` in result.json says which).
